# 범용 조회 후속 수정

평가 질문·정답·실패 사례를 읽거나 프롬프트/분기에 추가하지 않고, 실행 코드와 합성 기능 명세에서 확인한 문제를 수정했다. PR #66 B는 보존하며 이 변경은 `feat/grounded-query-validation`의 비활성 실험 경로에 적용된다.

## 변경

- 독립 SQL/Graph 내부 조인: 한쪽에만 있는 ID는 조인 결과에서 제외한다. NULL 키는 매칭하지 않고 중복 행의 다중도는 보존한다. 기존 코드는 오른쪽에만 있는 키를 선행 입력 범위 위반으로 처리했다. 입력 바인딩이 있는 종속 조회의 범위 검사는 유지한다. 기본 B 동작은 바꾸지 않는다.
- 조회 책임: 필요한 출력의 source가 라우팅에서 누락되면 라우터의 기존 한 번 복구 안에서 진단한다. 각 생성기에 전체 의존성 계획과 source 책임을 제공한다. 다른 source의 조건을 가짜 로컬 필드로 구현하지 않으며, 정렬/제한 전에 전체 조건을 적용하도록 명시한다.
- 공통 검증: 혼합 후보는 개별 쿼리뿐 아니라 실제 조합 방식, 입력 행 연결, 다중도, 집계 단위와 전체 정렬/제한을 별도 항목으로 검토한다. 서로 독립된 섹션을 합쳐진 결과로 간주하지 않는다. `verified`, `contradicted`, `unverified` 상태와 검토 완결성을 구분해 다음 후보에 진단을 전달한다. 모델 검토는 정확성의 증명이 아니다.
- 실행 증거: 검토 대상 쿼리가 실제 실행된 쿼리와 다르거나 결과가 `INCONCLUSIVE`이면 정상 빈 결과로 확정하지 않는다.
- 답변: 불필요한 행 선택 모델 호출을 제거했다. 10행 이내 결과는 모든 행·요청 필드를 조회 순서대로 렌더링한다. 큰 결과는 앞부분을 표시하고 요약 사실을 알린다. 원래 행의 값과 단위를 연결한다. 질문 해석 오류와 답변 구성 오류를 다른 코드/단계로 기록한다.

## 검증

- 단위/기능 테스트: 816개 통과.
- 실제 PostgreSQL/Neo4j 경계 테스트: 3개 통과. 모델 응답은 모의이며 실제 모델 정답률은 측정하지 않는다.
- 합성 SQLite 조인과 응용 조인 결과를 여러 데이터 상태에서 비교: 한쪽 전용 ID, NULL, 중복 다중도, 종속 조회 범위 위반을 검사했다.
- Ruff 및 mypy 228 파일 통과. 프런트엔드 코드는 이번에 변경하지 않았다.
- 실제 모델 기능 확인 3건은 API 연결 실패로 미완료. 자동 승인 검토가 새 기능 확인 질문·제조 스키마·조회 결과의 `api.openai.com` 전송을 이전 평가 승인과 별도 범위로 판단해 거절했다. 이 실패를 모델 품질 수치로 사용하지 않는다.

현재 UI/API는 PR #66 B를 계속 사용한다. 새 실험 코드를 운영으로 전환하거나 평가 정답률 상승을 주장하지 않는다. 실제 모델 기능 확인과 고정된 개선안의 비교 평가가 남아 있다.
