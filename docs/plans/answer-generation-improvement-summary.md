# 자연어 답변 형식 일관성 문제 — 팀 논의용

> **한 줄 요약**: 같은 질문을 해도 답변 형식이 매번 다르게 나옵니다. 원인은 AI가 매번 자유 문장을 새로 쓰기 때문이고, 해결책은 자주 나오는 단순 질문엔 고정 템플릿을 쓰는 것입니다. 구현 전에 방향을 팀과 맞추고 싶습니다.
>
> 상세 근거·수치는 [answer-generation-improvement-proposal.md](./answer-generation-improvement-proposal.md) 참고.

---

## 1. 문제 상황

같은 "재고 부족한 제품 알려줘" 질문을 두 번 실행했더니 답변 구조가 달랐습니다.

**답변 A** — 그룹으로 나눔
- "재고가 0인 제품" 소제목 + 목록 18개
- "부족량이 큰 제품" 소제목 + 목록 10개

**답변 B** — 그룹 없이 하나로
- "주요 부족 제품" 목록 하나에 14개
- 마지막에 "그 외에도 Flat Washer, Grip Tape... 등이 부족합니다" 문장 추가

같은 데이터인데도 ① 그룹으로 나누는지 ② 몇 개를 보여주는지 ③ 목록 밖 항목을 따로 언급하는지가 매번 달라집니다.

---

## 2. 왜 이런 문제가 생길까요

지금 구조는 조회된 데이터를 AI(LLM)에게 넘기고 **"이 데이터로 자연스러운 답변을 써줘"라고 매번 새로 시키는 방식**입니다.

자유 작문을 매번 새로 시키는 거라, 같은 자료라도 표현이 조금씩 달라지는 게 당연합니다 — 사람이 같은 보고서를 두 번 새로 쓰면 매번 문장이 달라지는 것과 같은 이치입니다.

---

## 3. 해결 방향: 두 갈래로 나누기

질문을 "단순한가 / 복잡한가"로 나눠서 다르게 처리합니다.

### 🟢 단순한 질문 → 고정 템플릿 (AI 호출 없음)

"재고 몇 개야?", "정가 얼마야?" 같은 **단일 값 / 짧은 목록** 질문은 AI를 아예 부르지 않고, 코드가 정해진 문장 틀에 값만 끼워 넣습니다.

```
"{제품명}의 재고는 {숫자}입니다."
```

- 형식이 항상 100% 동일
- AI를 안 부르니 비용·속도·오답 위험이 전부 0
- 지금 겪은 502 오류(정상 답변이 오탐으로 거부되는 문제)도 이 케이스에서는 원천적으로 재발 불가능

### 🟡 복잡한 질문 → AI가 "정해진 칸"만 채움

행이 많아서(예: 부족 제품 141건) 요약·비교가 진짜 필요한 질문은 AI가 여전히 필요합니다. 다만 자유 문장을 통째로 쓰게 두지 않고, **요약 한 줄 / 강조 항목 목록 / 주의사항**처럼 정해진 칸만 채우게 하고, 그 칸을 코드가 항상 같은 형식으로 조립합니다.

```json
{
  "summary": "재고가 부족한 제품은 총 73건입니다.",
  "highlighted": [{"name": "Lower Head Race", "value": 299}],
  "caveat": "전체 141건 중 일부만 표시됩니다."
}
```

- 항목 수, 그룹핑 여부가 매번 같은 규칙으로 고정됨
- 필드 단위로 값이 진짜 데이터에 있는지 확인 가능 (지금처럼 "이 한국어 단어가 원문에 있나" 식으로 억지로 대조할 필요 없음)

---

## 4. 데이터로 본 근거: 우리 질문 중 얼마나 단순할까?

평가용 골드셋(질문 35개) 기준으로 한 번 짜리 응답이 최대 몇 건까지 나오는지(`maxRows`) 집계했습니다.

| 결과 규모 | 개수 | 비율 | 해당 유형 |
|---|---|---|---|
| 5건 이하 | 18 | **51%** | 🟢 단순 — 고정 템플릿 대상 |
| 10~20건 | 7 | 20% | 중간 |
| 100건 | 3 | 9% | 대량 |
| 200건(사실상 무제한) | 7 | **20%** | 🟡 대량 목록 — 위 사례가 이 부류 |

**절반은 고정 템플릿만으로 해결**되고, **20%는 대량 목록**이라 반드시 두 번째 방향(🟡)도 같이 다뤄야 합니다.

---

## 5. 참고: 이미 진행 중인 관련 작업 (현재 일시정지)

로컬 전용 브랜치(`worktree-answer-visualization`, 원격 미push)에서 비슷한 방향의 작업이 이미 상당히 진행돼 있습니다.

- 결과가 1행이면 **KPI 카드**, 2~20행이면 **막대그래프**로 자동 렌더링 (LLM 없이 규칙 기반)
- API·대화기록·프론트까지 배선 완료, 테스트 있음
- **단, 20행 넘는 대량 목록은 커버 안 됨** — 위 사례가 정확히 이 빈틈

➡️ 이 문서의 작업을 시작하기 전에 **이 브랜치를 이어서 확장할지, 별도로 새로 만들지** 팀에서 먼저 정해야 중복 작업을 피할 수 있습니다.

---

## 6. 우선순위 제안

1. **🟢 고정 템플릿부터** — 위험 없고, 골드셋의 절반이 즉시 대상
2. **🟡 대량 목록의 구조화 처리** — 미루면 안 됨(빈도 20%로 낮지 않음). 단, 5번의 기존 워크트리와 범위 조율 먼저
3. **재시도 로직** — 검증 실패 시 AI에게 한 번 더 기회를 주는 저비용 보강, 1·2와 별개로 언제든 추가 가능
