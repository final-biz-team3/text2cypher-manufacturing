# 해석·출력 연결 복구 수정

기준: fb1fac9 평가 완료 후 수정. 평가 문항, 정답, 실패별 질문 표현은 구현에 사용하지 않았다.

- 물리 필드 참조의 대소문자·스키마 접두사 차이는 실제 스키마에서 하나로 식별될 때만 정규화한다. 모호하거나 존재하지 않는 필드를 추측하지 않는다.
- 해석 복구 요청에 이전 구조와 실제 오류를 전달한다. 복구 소진 시 원질문과 전체 스키마로 해석과 실행 계획을 함께 연결하는 제한된 복구를 수행한다. 기존 요청 전체 시간·호출 예산을 공유한다.
- SQL 조인을 Neo4j 관계로 표현하지 않도록 계약 설명을 분리했다. 계산 출력의 물리 근거와 출력 별칭도 구분했다.
- 단계 내부 출력과 최종 사용자 출력의 ID 영역을 분리했다. 최종 출력 누락·추가는 계속 거절하며 내부 결합 필드는 사용자 결과에 노출하지 않는다.
- 계획 복구에는 거절된 실제 계획을 전달한다. 복구 후보도 실행 전 가드와 공통 의미 검증을 거친다.

검증: 전체 백엔드 862개 통과 후 복구 경로 2개 테스트 추가 통과. 실행 계획 테스트 총 48개 통과. Ruff, Black 및 mypy 238개 소스 통과.
실제 모델 병렬 개발 확인 3건: 제품 행 수 504, 제품 ID 음수 조건 정상 빈 결과, SQL·Graph 제품 개수 각각 504를 반환했다. 22.54~41.07초. 이는 개발 스모크 확인이며 일반화 정확도 개선의 증거가 아니다. 해당 개발 질문은 이번 수정 전에도 통과했던 기능이다.

운영 B와 기존 평가 실행 원본은 유지했다. 엄격 경로 지원 범위는 이번 변경에서 확대하지 않았다. 새 복구는 기존 #61 전체 파이프라인을 호출하는 방식이 아니며, 공통 계획 안에서 수행한다. 전체 90/120문항 비교는 재실행하지 않았으므로 수정 후 성공률은 아직 미측정이다.
