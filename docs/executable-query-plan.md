# 범용 제조 질의 실행 계획

## 활성화와 호환

기본 `GROUNDED_QUERY_ENABLED=false`는 B 동작을 유지한다. 비교용 프로세스에서 `true`를 설정하면 `GROUNDED_PLAN_VERSION=2`(기본)를 사용한다. `1`은 이전 실험 경로의 회귀 검증에만 사용한다. 보존된 B worktree는 수정하지 않는다.

## 처리 계약

`Meaning`은 읽기/쓰기, 스키마상 지원 여부, 구조화된 요구사항, 요청별 출력 ID를 분리한다. 전체 실제 스키마와 출처 문서를 제공하며 스키마 타입 수를 실제 행 수로 해석하지 않는다. 고유 이름만 기존 엔티티 검색으로 연결한다. 문서상 모호함에는 확인 질문 한 개를 반환한다.

`QueryPlan`은 원천 조회 최대 4개와 선언적 결과 연산 최대 8개를 가진다. 단계 ID로 결과를 저장하며 독립 단계만 동시 실행한다. 파라미터는 행 배열로 연결해 NULL과 여러 필드의 결합을 보존한다. 필터·투영·중복 제거·집계·정렬·제한·inner/left/semi/anti join을 지원한다. 잘린 중간 결과에 연산하거나 전체 집계로 답하지 않는다.

엄격 경로는 단일 SQL 물리 필드 조회의 확인 가능한 기능 교집합으로 보수적으로 제한한다. 카탈로그의 집계 이름만으로 계산식·그룹 기준의 동등성을 증명할 수 없는 집계와 Graph/혼합/DAG는 범용 계획으로 보낸다. 이는 엄격 경로의 전체 기능을 재현한다는 뜻이 아니다. 엄격 후보의 출력은 실제 SQL 표현식으로 매핑하고 동일 검증을 적용한다.

SQLGlot의 PostgreSQL AST로 연산자·값·조건 결합·집계·그룹·제한을 부분 검증한다. 중첩 쿼리 등 판정 불가 범위는 검토에 남긴다. Cypher의 단순 명시적 관계 패턴은 타입·방향·깊이를 비교하되 범위·부정·필터·카디널리티의 의미 증명으로 취급하지 않는다. 나머지는 원질문·문서·실제 쿼리/연산 근거를 사용해 검토한다.

검토 거절에는 원문 구간과 단계가 연결된 issue가 필요하다. 모순된 검토는 검토 자체를 한 번 복구하며 쿼리를 다시 생성하지 않는다. 실제 후보 결함은 진단을 전달해 대안 후보 한 번을 시도한다. 정상 빈 결과의 조건은 완화하지 않는다.

요청 전체 120초, 후보당 45초, 실제 SDK 호출 12회가 기본 한도다. 내부 SDK 자동 재시도는 비활성화하고 엄격 경로 호출도 같은 예산으로 집계한다. 각 DB의 읽기 가드/권한과 기존 쿼리 제한은 유지한다.

## API와 답변

선택 필드 `status`는 answered/empty/clarification/unsupported/unanswerable/unverified/blocked/error를 구분한다. `result.sections`는 최종 열 ID·표시명·타입·단위·행·잘림을 제공한다. UI와 자연어 텍스트는 같은 최종 결과를 사용한다. 자연어 답변은 각 섹션 앞 10행의 모든 공개 필드를 결정적으로 렌더링하며 참조를 기록한다. 내부 조인 열은 노출하지 않는다. 기존 자연어 생성 모델을 새 경로에서 추가 호출하지 않는다. 저장 기록은 기존 JSON에 버전 메타데이터를 보존해 스키마 마이그레이션 없이 호환한다.

## 한계와 운영

검토 모델의 수용은 의미 정확성의 증명이 아니다. 추가 쿼리 조건·어려운 관계 조합·업무 의미 누락은 독립 평가가 필요하다. B 대비 질문 단위 정확도 개선의 95% 신뢰구간 하한 양수, 유형별/지원 기능 퇴행 없음, 평균 호출 수와 p95 지연 각각 B의 1.5배 이내가 확인되기 전 서비스는 B를 유지한다.
