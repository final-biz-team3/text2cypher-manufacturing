# 적응형 제조 질의 경로 (버전 3)

운영 B 및 linking-recovery-v1 평가 작업 공간을 보존하기 위해 feat/adaptive-query-routing 작업 트리에서 구현했다. GROUNDED_QUERY_ENABLED=true와 GROUNDED_PLAN_VERSION=3일 때만 활성화한다.

- 초기 해석은 읽기/쓰기, 필요한 DB, 원문 조건, 공개 출력, 고유 이름, 확인 질문만 표현한다. 정확한 물리 필드·관계·단위 계약을 초기 진입 조건으로 요구하지 않는다.
- SQL 또는 Graph 하나로 가능한 질문은 실제 기존 agents.sql.generator.generate_sql / agents.cypher.generator.generate_cypher를 호출한다. 이는 기존 생성기 재사용이며 #61 전체 라우팅/합성 파이프라인 복제는 아니다.
- 단일 쿼리의 공개 출력은 별도 바인딩으로 연결하고 요구사항/출력 ID는 코드에서 발급한다. 중간 컬럼은 최종 출력과 분리한다. 값 일치로 별칭을 연결하지 않는다.
- 혼합/미확정 소스 및 대안 후보에는 공통 실행 계획을 사용한다. 후보 최대 2개, 요청 120초·12회 모델 호출, 후보당 45초 제한을 유지한다.
- 이름 엔티티 및 사용자 확정 엔티티는 모든 후보 생성 전에 확인하고 생성기·검토기에 전달한다. 버전 2 복구 경로에서도 엔티티 확인 전 계획은 재사용하지 않는다.
- 실제 경로 이름 legacy_sql, legacy_graph, structured_plan, structured_alternative을 기록한다. 일반 계획을 pr61로 잘못 표시하지 않는다.
- 검토 JSON 형식 오류는 같은 쿼리에 대한 검토 복구로 처리하고 조회 후보 오류로 취급하지 않는다. 복구 실패를 통과시키지 않는다.
- 읽기 가드, 정상 빈 결과, 잘림 보호, 최종 결과와 답변의 동일 출처를 유지한다.

제한: 일반 속성값 전체를 검색하는 새 검색기는 도입하지 않았다. 이름 값 확인은 기존 resolver를 사용한다. 단일 후보의 자연어 조건 검증은 여전히 검토 모델이 필요하며, 모델 검토를 의미 정확성 증명으로 간주하지 않는다. 복잡한 혼합 경로에는 기존 공통 계획의 표현 범위가 적용된다.

기능 검증은 평가 문항 내용이 아닌 합성 명세로 작성했다. 실제 모델 및 90/120문항 재평가는 별도 고정 실행으로 수행하며, 기존 실행과 부하를 겹치지 않는다. 운영 전환은 성능 결과 확인 전까지 하지 않는다.
