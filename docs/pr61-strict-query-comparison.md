# PR #61 원본과 엄격한 질의 경로 결합 비교

## 고정한 코드

- A: PR #61 `feat/query-retry-improvement`, `3e24d123ab4c66e7de7b37c18ee570de8031dbe3` 원본.
- B: 같은 커밋에서 만든 `feat/pr61-strict-query-fallback`.
- 1차 경로: PR #47 병합 커밋 `61169c23514f3b497e521ff97a1917f50bfd681e`의 엔티티 식별·계획·쿼리 생성·실행·결과 조합 코드.

PR #47의 89/90은 source 평가였고 PR #61의 235/270은 전체 운영 경로 평가였다. 두 기록을 직접 비교하지 않고 같은 질의셋·모델·DB로 다시 측정한다. 이전에 테스트한 origin/dev는 #61이 병합되기 전 코드이므로 이번 A 기준선으로 사용하지 않는다.

## 동작

공통 요청 가드와 주제 판별을 통과한 질문을 이전 엄격한 질의 경로로 먼저 처리한다. 정상이며 비어 있지 않고 잘리지 않은 결과는 #61의 기존 자연어 답변 노드로 보낸다. 초기화 실패, 예외, query_failure, 조합 오류, 빈 결과 또는 잘린 결과는 원질문과 확정 엔티티만으로 #61 질의 경로를 새로 시작한다. 이전의 중간 엔티티·SQL·결과·오류를 다음 시도에 전달하지 않는다. 빈 결과도 재확인하므로 정상적인 무자료 질문에 추가 비용이 들 수 있다.

엄격한 시도는 기본 60초이며 `STRICT_QUERY_TIMEOUT_SECONDS`로 유한한 양수를 설정할 수 있다. 시간 초과 시 해당 작업을 취소하고 #61로 전환한다. 사용자가 전체 요청을 취소한 경우는 삼키지 않는다. 이전 경로의 초기화가 실패해도 #61 경로를 유지한다.

두 경로 모두 현재 #61의 SQL/Cypher 읽기 전용 가드와 DB 실행기를 사용한다. #61의 요청 가드, 자연어 답변, API, 대화기록, frontend는 변경하지 않는다. 이전 답변 코드는 복사하거나 호출하지 않는다. 기존의 `추가해줘` 오차단은 두 버전에서 동일하게 남아 있으며 이번 비교에서 임의로 질문이나 가드를 바꾸지 않는다.

## 이식 범위와 출처

`backend/strict_query/snapshot/`은 이전 질의 처리의 의존성 29개 모듈을 별도 namespace로 보관한다. 런타임에는 Git, 다른 worktree, 평가 manifest 또는 Gold 파일을 읽지 않는다. 이전의 API·인증·자연어 답변·UI는 포함하지 않는다. 현재 운영 모듈을 교체하지 않고 분리했기 때문에 코드량은 늘어난다.

`snapshot_manifest.json`은 원본 커밋, 파일별 원본 SHA-256, 이식본 SHA-256과 호환성 변경을 기록한다. 변경은 import 격리, 최신 예외의 lookup_name 인자, 최신 실패 stage 타입 호환성, 공개 시도 이력에 원본 오류 대신 기존 안전 메시지를 기록하는 부분이다. 재시도 생성기에 제공하는 원본 오류 피드백과 이전 질의 판단 로직은 유지한다.

`query_strategy`와 `strict_attempt`는 내부 관측 필드다. 실제 사용된 경로, 수용/전환 여부, 전환 사유와 소요 시간을 평가 어댑터가 기록한다. API 응답 필드는 추가하지 않는다.

## 검증과 평가 계획

- #61 원본 전체 비통합 테스트: 760개 통과.
- 결합 버전: 전체 비통합 테스트 773개 통과(통합 9개 제외), Ruff/Black/mypy 전체 통과.
- 실제 로컬 PostgreSQL·Neo4j + 고정 MockOpenAIClient 연결 테스트: SQL·Graph 2개 통과. 외부 모델 호출 없음.
- 양쪽 모두 기존 90개·신규 일반화 90개 Gold 사전 검증 통과.
- 실제 비교: 기존 90개 × 3회, 신규 90개 × 3회, A/B 두 버전. 총 1,080 case-run.
- 모델/effort: gpt-5.6-luna / medium. 같은 고정 제조 DB snapshot과 Gold 사용.
- 현재 실제 모델 평가는 자동 승인 검토에서 외부 전송 재승인을 요구해 실행되지 않았다. 위 단위·연결·Gold 검증은 정답률 실측을 대신하지 않는다.

평가 어댑터는 기존 작업 폴더의 `artifacts/pr61-comparison/run.py`에 있다. `baseline|candidate`, `existing|generalization` 인자로 각각 실행하며 원본 결과를 별도 경로에 남긴다. 준비 단계에서 모델 프롬프트나 평가 정답을 조정하지 않았다.

## 가설의 한계

이전 경로가 반환한 결과의 의미가 틀렸지만 계약을 통과하면 2차 경로로 넘어가지 않는다. 운영에서는 Gold 정답을 알 수 없으므로 모든 질문에 무조건 정답을 보장할 수 없다. 이번 실험은 기존 정답률 유지, 신규 질문의 회복, 전환 후 회복률, 오수용, 추가 모델 호출과 지연을 함께 확인하기 위한 것이다. 자연어 문구가 있다는 것과 정답 데이터가 있다는 것은 별도로 집계한다.
